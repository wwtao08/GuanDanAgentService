# 掼蛋教练 UI 优化文档 v2.1

## 概述

本文档详细描述 v2.1 版本的 UI 优化内容，包括手牌尺寸调整、出牌位置优化、教练提示流程改进等。

## 修改清单

### 1. 手牌尺寸优化 (HandCards.vue)

#### 优化目标
- 减少手牌占用的屏幕空间
- 提升整体界面的紧凑度
- 保持良好的可读性

#### CSS 变量调整

| 变量名 | 原值 | 新值 | 变化幅度 |
|--------|------|------|----------|
| `--card-w` | 60px | 46px | -23% |
| `--card-h` | 85px | 66px | -22% |
| `--stack-overlap` | 55px | 45px | -18% |
| `--font-size-lg` | 1.3rem | 1rem | -23% |
| `--font-size-md` | 1rem | 0.85rem | -15% |
| `--font-size-sm` | 0.9rem | 0.75rem | -17% |

#### 样式调整详情

```scss
// 调整前
.hand-cards {
  --card-w: 60px;
  --card-h: 85px;
  --stack-overlap: 55px;
  padding: 12px 12px 16px;
  gap: 8px;
  height: 180px;
}

// 调整后
.hand-cards {
  --card-w: 46px;
  --card-h: 66px;
  --stack-overlap: 45px;
  padding: 10px 10px 12px;
  gap: 6px;
  height: 140px; // 节省 40px 垂直空间
}
```

#### 卡牌选中状态
- 保持上移效果，调整上移距离: 10px → 8px
- 保持高亮边框效果

### 2. 出牌位置优化 (PlayedCards.vue)

#### 优化目标
- 让其他玩家的出牌更靠近各自的玩家信息
- 提升游戏区域的空间利用率
- 改善视觉层次感

#### 位置调整

| 玩家位置 | 调整项 | 原值 | 新值 |
|----------|--------|------|------|
| 上方玩家 | top | 80px | 65px |
| 左侧玩家 | left | 95px | 10px |
| 右侧玩家 | right | 95px | 10px |

#### 已出牌尺寸调整

| 属性 | 原值 | 新值 |
|------|------|------|
| width | 36px | 28px |
| height | 50px | 40px |
| font-size | 14px | 11px |
| border-radius | 4px | 4px (保持) |

#### 布局示意图


### 3. 教练提示优化 (CoachHintPanel.vue)

#### 优化目标
- 简化用户操作流程
- 默认提供更有价值的高手提示
- 减少不必要的点击

#### 默认模式变更
- 调整前: 默认新手模式 (`'novice'`)
- 调整后: 默认高手模式 (`'expert'`)

#### 按钮移除
- 移除次级页面中的"教练提示"按钮
- 简化界面布局

#### 自动请求逻辑
```typescript
// 监听模式变化，自动请求提示
watch(coachMode, (newMode) => {
  if (props.visible) {
    emit('request', newMode)
  }
})
```

### 4. 聊天窗口整合 (GameView.vue)

#### 优化目标
- 避免聊天功能重复
- 统一使用团队聊天系统
- 简化界面复杂度

#### 移除内容
- 移除 `ChatWindow` 组件引用
- 移除 `handleSendMessage` 函数
- 移除 `handleSendEmoji` 函数

#### 保留内容
- 保留 `TeamChatPanel` 组件
- 保留团队聊天相关逻辑

### 5. 自动请求逻辑 (GameView.vue)

#### 新增状态变量
```typescript
const hasRequestedCoachHint = ref(false)
```

#### 监听逻辑
```typescript
// 监听教练提示页面显示状态
watch(
  () => [showCoachHint.value, coachShell.value] as const,
  ([newShow, newShell]) => {
    const lock = newShow && newShell === 'coach'
    document.body.style.overflow = lock ? 'hidden' : ''
    
    // 进入教练提示页面且未请求过提示时，自动请求高手提示
    if (newShow && newShell === 'coach' && !hasRequestedCoachHint.value) {
      hasRequestedCoachHint.value = true
      handleCoachHint('expert')
    }
  },
  { flush: 'post' },
)

// 退出教练提示页面时重置状态
watch(showCoachHint, (ok) => {
  if (!ok) {
    coachShell.value = 'hand'
    hasRequestedCoachHint.value = false
  }
})
```

## 交互流程对比

### 教练提示流程对比

#### v2.0 (旧流程)
```
1. 点击"教练提示"
2. 进入提示页面（默认新手模式）
3. 点击"教练提示"按钮
4. 等待提示返回
5. 切换到高手模式
6. 再次点击"教练提示"按钮
7. 查看高手提示
```

#### v2.1 (新流程)
```
1. 点击"教练提示"
2. 进入提示页面（默认高手模式）
3. 自动请求并显示高手提示
4. 如需切换模式，点击切换后自动重新请求
```

**改进点**: 减少 4 次点击操作，流程更顺畅

### 聊天系统对比

#### v2.0 (旧系统)
- 两个聊天窗口同时存在
- 用户可能困惑使用哪个
- 功能重叠

#### v2.1 (新系统)
- 只有团队聊天面板
- 功能更聚焦
- 界面更简洁

## 性能影响

### 正面影响
1. 手牌区域更小 → 渲染更快
2. 已出牌更小 → DOM 元素尺寸减小
3. 移除一个聊天组件 → 组件树更简单

### 无影响
- 自动请求逻辑开销极小
- 模式切换监听性能可忽略

## 用户体验改进

### 减少操作步骤
- 教练提示流程: 7 步 → 3 步，减少 57%

### 更合理的默认值
- 高手模式默认 → 提供更有价值的建议

### 更清晰的界面
- 移除重复功能 → 减少用户困惑
- 紧凑布局 → 更多空间展示游戏内容
